# ピカイチ採用 コンディションボード — GAS 版

スプレッドシートに貼るだけで動く Apps Script 版。数字はすべてシートから読むので、
**決定者を1行足せばダッシュボードが最新化される**。毎月HTMLを作り直す必要はない。

```
Code.gs          集計ロジックとメニュー。触るのは基本 CONFIG だけ
Dashboard.html   画面。CSSとチャート描画（外部読み込みなし）
appsscript.json  マニフェスト（タイムゾーン・ウェブアプリ設定）
```

---

## 1. 設置（5分）

1. スプレッドシートを開く → **拡張機能 › Apps Script**
2. デフォルトの `コード.gs` の中身を消して `Code.gs` を全文貼る
3. 左の **＋ › HTML** で `Dashboard` という名前のファイルを作り、`Dashboard.html` を全文貼る
   - ファイル名は拡張子なしで `Dashboard`。`Code.gs` 側が `createTemplateFromFile('Dashboard')` で参照する
4. マニフェストを合わせる場合は、⚙ プロジェクトの設定で「`appsscript.json` を表示」をONにして貼る
5. 保存 → スプレッドシートを**再読み込み**すると、メニューに **「ピカイチ採用」** が出る

初回はメニューから何か実行したときに認可を求められる。「詳細 › 安全ではないページに移動」から許可する
（自分が書いたスクリプトなので想定どおり）。

## 2. 初期セットアップ（1クリック）

**メニュー › 初期セットアップ（最初に1回）** を実行する。これだけで次が済む。

- `決定者マスタ` を作成し、**2026年7月30日時点の決定者16行**（締結15名＋締結後辞退1名）を投入
- 既存のファネルシートが無ければ `月次目標` を作成し、FY2026の月次目標・実績を投入
- `選考中一覧` が無ければ作成し、**選考中15名**（確度付き）を投入
- 続けて設定を診断し、どのシートを掴めたかを表示

**新規の空スプレッドシートでも、既存の「ピカイチ進捗管理シート」でも、これ1回で動く。**
何度実行しても既存の行は消えず、氏名が未登録の行だけ追加される。CONFIG を触る必要もない。

### 既存のファネルシートを使う場合

`CONFIG.funnelSheet` を実際のシート名に合わせる（既定は `ピカイチファネル`）。
「目標」「実績」というラベルが並ぶ行を探して12か月分の列ペアを自動検出するので、
列を挿入しても追従する。指標行は `1. 情報数` `4. 面接数` `6. 内定数` `8. 締結数` を
行頭の前方一致で探す（ラベルが違う場合は `CONFIG.funnelRows` を直す）。

読めなかった場合は自動で `月次目標` シートにフォールバックする。診断画面に
どちらから読んだかが出る。

### 月次目標シート（フォールバック / 新規スプシ用）

`指標` × `1月〜12月` の素直な表。

| 指標 | 1月 | 2月 | … | 12月 |
| --- | --- | --- | --- | --- |
| 情報数 目標 | 1 | 2 | | 5 |
| 情報数 実績 | 1 | 5 | | 0 |
| 面接数 目標 | 1 | 1 | | 2 |
| … | | | | |
| 締結数 目標 | 0 | 0 | | 1 |
| 締結数 実績 | — 入力不要 | | | |

**締結数の実績は決定者マスタから自動算出する**ので入力しない。
ここを一本化しているので、締結後辞退の扱いでファネルとHCがずれることがない
（従来シートで締結16名／実効15名の二重定義が起きていた原因）。

### 決定者マスタの列

1候補者1行。区分のドロップダウンと日付・金額の書式は自動で入る。

| 列 | 内容 | 備考 |
| --- | --- | --- |
| 氏名 | | |
| 区分 | POP / ピカイチ / 準ピカイチ / その他 | ドロップダウン。**WBはここから自動算出**するので WB 列は持たない |
| 締結日 | 業務委託契約の締結日 | Salesforce の `ContractConclusionDate` を正とする |
| 参画予定日 | | 参画月の分布と、今月の決定カードに使う |
| 応募チャネル | リストマッチ / リファラル / 直接応募 など | 自由記述。出てきた値で自動集計する |
| 出身企業 | | 集中度アラートの判定に使う |
| 経歴・実績 | 前職での売上・年収・ランキング、リファラル経緯など | **ど頭の決定者カードに出る本文**。未入力だと「未入力」と表示され件数が出る |
| リファラル元 | | |
| 売上期待値(万円) | 集客戦略MTGで算出した年間売上見込 | **未入力だと保証率が算定できない**（アラートが出る） |
| 年収保証(万円) | | |
| 固定給計(万円) | 月額×期間の合計 | |
| サインアップ(万円) | | |
| ステータス | 締結 / 辞退（締結後） | **辞退（締結後）は HC・WB から自動で除外される** |
| 備考 | | |

### 選考中一覧

`CONFIG.pipelineSheet` のシートで `採用フェーズ` という見出しのセルを探し、その列でフェーズ別に集計する。

- `締結` `辞退` を含むフェーズは除外し、`ペンディング` `保留` は別枠で数える
- **確度**は見出しに「確度」を含む列を部分一致で探す（`採用確度` でも拾う）。値に「高」が入っていれば
  確度「高」としてカウントし、当期の残り締結目標と突き合わせて充足しているか判定する
- 列順は自由。見出し名で探すので挿入・移動しても追従する
- シートが無ければパイプラインの節は出ない（他の節は動く）

## 3. 使う

| やりたいこと | 操作 |
| --- | --- |
| ダッシュボードを見る | メニュー › **ダッシュボードを開く**（スプシ内のモーダルで開く） |
| 決定者を追加する | `決定者マスタ` に1行足すだけ。ダッシュボードを開き直せば反映される |
| URLで共有する / スマホで見る | 下記「ウェブアプリとして公開」 |
| Looker Studio や他シートから参照する | メニュー › **集計シートを更新** → `集計_ピカイチ` シートに縦持ちで書き出す |
| 設定が合っているか確認する | メニュー › **設定を診断** |

### ウェブアプリとして公開（直リンクを取る）

1. Apps Script エディタ右上の **デプロイ › 新しいデプロイ**
2. 歯車（種類の選択）→ **ウェブアプリ**
3. **次のユーザーとして実行**： 自分（`USER_DEPLOYING`）
4. **アクセスできるユーザー**： Terass 内の全員（ドメイン限定）
5. **デプロイ** → 表示される **ウェブアプリの URL** が直リンク

```
https://script.google.com/a/macros/terass.com/s/AKfycb.../exec
```

「自分として実行」にしておくと、閲覧者はスプレッドシートの閲覧権限が無くても
ダッシュボードだけ見られる。数字を見せたいが元シートは触らせたくない相手に向く。

**URL を変えずに更新する**： コードを直したあと **デプロイ › デプロイを管理 › ✏️ 編集 →
バージョン「新バージョン」→ デプロイ**。ここで「新しいデプロイ」を選ぶと**別のURLが発行される**ので、
共有済みのリンクを保ちたいときは必ず「デプロイを管理」から更新する。

初期セットアップ前に URL を開くと、生のエラーではなく「まだデータがありません」の
案内画面とスプシへのリンクが出る。

### 毎朝自動で集計シートを更新する

エディタ左の ⏰（トリガー）から `writeSummarySheet` を日次で実行するトリガーを追加する。

## 4. 画面の中身

| ブロック | 内容 |
| --- | --- |
| **今月の決定** | ど頭。当月のHC・WBと目標差分＋決定者カード（氏名・区分/WB・出身企業・経歴と実績・参画予定月・締結日・売上期待値・保証コミット）。当月がまだ0名なら直近で決定のあった月の内訳に切り替わる |
| いま出ている警戒サイン | 判定ルールによる自動抽出。しきい値を超えたものだけ出る |
| **月次の決定状況（HC / WB）** | ファーストビュー。累計HC・累計WB・平均WB・直近3か月平均WB＋月次の積み上げ（区分別）＋月次テーブル |
| ファネル形状と歩留まり | 情報→面接→内定→締結と各歩留まり、決定者出現率 |
| 月次推移 | 情報数・締結数の 目標 vs 実績 |
| 決定者の構成 | 区分別・応募チャネル別・出身企業別 |
| 投資規律 | 個別の保証率と66%ルール超過 |
| 参画月の分布 | オンボーディング負荷 |
| 残パイプライン | 当期の残り締結目標に対する充足判定＋フェーズ別の人数・候補者・確度 |

### 自動アラートの判定ルール

`Code.gs` の `buildAlerts_()` に定義してある。増やしたい条件は同じ形で足せる。

| レベル | 条件 |
| --- | --- |
| 警戒 | 当期の情報数の進捗率 < 時間進捗率（＝入口の失速） |
| 注意 | HC達成率 ≧ 100% かつ WB達成率 < 100%（人数は達成・WBは未達） |
| 注意 | 直近3か月の平均WB < 通期平均WB（単価ミックスの劣化） |
| 注意 | 保証率が 66% を超えた決定者がいる |
| 注意 | 売上期待値が未登録の決定者がいる |
| 注意 | 単一の出身企業が決定者の 70% 以上 |
| 注意 | 同一月の参画が 5名以上 |

しきい値は `CONFIG.wbBenchmark`（参考目標WBの係数）と `CONFIG.guaranteeCapRate`（保証上限率）で変えられる。

## 5. 設計上の約束

- **締結数は辞退控除後の実効値**。ステータス「辞退（締結後）」の行は HC・WB から外す
- **締結月は Salesforce の `ContractConclusionDate` を正とする**（Notion の「契約締結月」とは月替わりを跨いでずれる）
- **WBは区分から算出する**。区分と WB を二重に持たない
- **参考目標WB は HC目標 × 3.0 の仮置き**。WB目標が正式に決まったらファネルシートに行を足して読み替える
- **締結実績はマスタが唯一の正**。シート側の締結実績は読まずマスタから上書きする
- チャートは外部ライブラリを使わない（社内ドメイン限定公開でも読み込み失敗が起きないように）

## 6. 動かないとき

| 症状 | 原因と対処 |
| --- | --- |
| メニューが出ない | スプレッドシートを再読み込みする。それでも出なければ `onOpen` を一度手動実行して認可する |
| 何から始めればいいか分からない | メニュー › 初期セットアップ（最初に1回） |
| 「決定者マスタ シートがありません」 | メニュー › 決定者マスタを作成 / 初期化 |
| ファネルが空 | 「目標」「実績」ラベル行が検出できていない。設定を診断で確認し、`CONFIG.funnelSheet` を直す |
| 特定の人のWBが0 | 区分が未設定。設定を診断が対象者名を出す |
| 保証率が「—」 | 売上期待値(万円) が未入力 |
