# ピカイチ採用 コンディションボード

`pikaichi-condition-board.html` — ピカイチ採用（Terass Agent のトップ層狙い撃ち採用）の
コンディションを1枚に集約したダッシュボード。単一HTMLで完結し、外部リソースを一切読まない。

## 構成

| ブロック | 内容 |
| --- | --- |
| 月次の決定状況（HC / WB） | ファーストビュー。累計HC・累計WB・平均WB・直近3か月平均WB＋区分別の月次積み上げ |
| いまのコンディション | 入口／決定力／決定量／投資規律の4信号と総括 |
| ファネル形状と歩留まり | 年間累計 情報26 → 面接19 → 内定19 → 締結15 と各歩留まり |
| 月次推移 | 情報数・締結数の 目標 vs 実績（上期／下期の区切り付き） |
| チャネル構成 | オーガニックピカイチ／通常リファラル／自社サイト／その他 の集中度 |
| 決定者プロフィール | WB構成、応募チャネル、参画月の分布 |
| 投資規律 | 個別の保証率と66%ルール超過の可視化 |
| 残パイプライン | 選考フェーズ別の残数と内定後辞退者の再アプローチ管理 |
| 注視すべき4点 | 警戒／注意の判定と打ち手 |
| データ整備の申し送り | 集計がブレる4か所と対応方針 |

## データソース

- **ファネル・パイプライン・集客戦略**: ピカイチ採用管理シート（Google スプレッドシート）
- **決定実績**: Notion「決定候補者ログ」データベース
- **定義・ルール**: Notion「ピカイチ採用とは?」「KPI管理」

基準日 2026年7月30日時点のスナップショット。数値は上記ソースから手動で確定させたもの。

## GAS 版（毎月の運用用）

`gas/` に Apps Script 版がある。スプレッドシートに貼れば、決定者マスタに1行足すだけで
HC・WB・保証率・アラートが自動で再計算される。月次の運用はこちらを使う。
導入手順は `gas/README.md` を参照。

| | このHTML | GAS版 |
| --- | --- | --- |
| データ | 基準日時点で手動確定 | シートから毎回読む |
| 更新 | スクリプトで再生成 | シートを直すだけ |
| 解釈・打ち手 | 文章で書き込んである | ルールベースの自動アラート |
| 用途 | 経営会議に出すスナップショット | 日常のモニタリング |

## 再生成

チャートのSVGはスクリプトで生成している（座標計算をハンドコードしないため）。

```
python3 _build_charts.py   # charts.json にSVGを出力
python3 _build_page.py     # charts.json を埋め込んでHTMLを生成
```

- `_build_charts.py` — 各チャートのSVG生成。データは同ファイル冒頭の定数を書き換える
- `_build_page.py` — CSS（テーマトークン）と本文。プレースホルダにSVGを差し込む

## 更新時の注意

1. 締結数は**辞退控除後の実効値**で数える（シートの「06 CS締結」には締結後に辞退した候補者が残る）
2. 締結月は SF の `ContractConclusionDate` を正とする（Notion の「契約締結月」と月替わりを跨いでずれる）
3. 決定者出現率の月次値は使わない（リードタイム約71日を無視した同月比のため）。累計値、将来的には情報獲得月でのコホート値を見る
4. 新規決定者は集客戦略シートに売上期待値を登録してから保証率を算定する

## デザイン

配色・タイポグラフィはテーマトークンとして `:root` に定義し、`prefers-color-scheme` と
`data-theme` の両方でライト／ダークを切り替える。データマークの色は単一色相の
オーディナルランプで、コントラスト・CVD分離を検証済み。状態色（良好／注意／警戒）は
アクセント色とは分離し、必ずラベルを伴わせている。
