# 強み診断（Strengths Survey）

Googleフォームで回答 → 回答シートを **HTMLファイルに貼り付け** → その場で全員分のレポートが出る、
これだけの社内向け強み診断です。サーバー・API・課金・スクリプトの常駐は一切ありません。

- **測るもの**: 12テーマ（4領域 × 3）を60問で測定。回答は約10分
- **出るもの**: チーム一覧（ヒートマップ）／テーマ別の上位者リスト／個人レポート（印刷・PDF可）
- **データの扱い**: 貼り付けた回答はブラウザの中だけで処理され、外部には送信されない
- **採点は決定論的**: LLMは使わない。同じ回答からは必ず同じ順位が出る

---

## 1. 使うファイルは2つ

| ファイル | 役割 | 使う回数 |
|---|---|---|
| `form-generator.gs` | 60問のGoogleフォームと回答シートを自動生成する | 最初の1回だけ |
| `report.html` | 回答シートを貼るとレポートが出る | 回答が溜まるたび |

---

## 2. セットアップ（最初の1回、10分）

### フォームを作る

1. https://script.google.com を開き「新しいプロジェクト」
2. `form-generator.gs` の内容を全文貼り付けて保存
3. 上部の関数選択で **`createStrengthsForm`** を選び「実行」→ 権限を承認
4. 下の「実行ログ」に3つのURLが出る
   - **回答用URL** → これを配布する
   - フォーム編集URL → 文言を直したいとき用
   - **回答シート** → 回答がここに溜まる

> 手作業でフォームを作ってもかまいません。その場合は `docs/items.md` の60問を「均等目盛（1〜5）」で作り、
> 「氏名」の質問を必ず入れてください。設問文はコピペで完全一致させると確実です（グリッド形式でも認識します）。

### レポートを出す

1. `report.html` をダブルクリックしてブラウザで開く（Chrome / Edge / Safari 最新版）
2. 回答シートを開き、**Ctrl+A（⌘A）→ Ctrl+C** でシート全体をコピー
3. `report.html` の枠に貼り付けて「レポートを作成」

CSVでダウンロードしたファイルを「ファイルを選択」で読み込んでも同じです。
まず「サンプルデータで試す」を押すと、架空の12人分で画面の動きが確認できます。

---

## 3. 画面の見方

| タブ | 何が分かるか | 使いどころ |
|---|---|---|
| **チーム一覧** | 人 × 12テーマのヒートマップ。青いほどその人の中で優先度が高い資質 | チームの偏り、誰がどの領域を担っているか |
| **テーマ別の上位者** | 各テーマを上位5に持つ人のリスト（相対スコア順） | 「この仕事、誰に任せるか」の一次候補出し |
| **個人レポート** | 総括文・相対スコア・強みTop5の解説・控えめな面の補い方・アサイン担当者向けメモ | 本人へのフィードバック、1on1、配置検討 |

- 「全社との比較」は回答者が **10人以上** になると選べます。それまでは個人内の相対順位のみです
- 「結果をCSVで保存」で、素点・Z・順位を表形式に書き出せます（Sheetsで他データと結合する用）
- 「全員分をまとめて表示」＋「印刷 / PDF保存」で、1人1レポートのPDFを一括出力できます
- ⚠ が付いた人は回答品質に注記があります（同じ選択肢が続いた、逆転項目と食い違うなど）。結果は参考程度に読んでください

---

## 4. 設計の考え方

**強みは「個人内の相対順位」で決める。**
全項目に高く答える人と低く答える人がいるため、素点をそのまま比べると回答スタイルの差を測ってしまいます。
12テーマの素点を本人の平均・標準偏差で標準化（個人内Z）し、その人の中での順位として Top5 を出しています。
人と人を比べたいときは別軸の「全社との比較」を使います。

**逆転項目で回答の質を見る。**
各テーマに1問ずつ逆転項目（あてはまるほどテーマが低い文）を置き、「すべて5」のような読み飛ばしを検出して注記します。

**レポート文はテンプレートで組む。**
テーマ辞書（定義・現れ方・向く仕事・出すぎたときの副作用・1on1の問い）を、確定した順位に沿って組み合わせています。
生成AIを使わないので、結果に再現性があり、説明もつきます。

---

## 5. 運用上のルール（重要）

- **人事評価・選考の判断材料には使わない。** 妥当性検証が済んでいない自己申告データを評価に使うと、納得感と信頼を損ないます。用途は育成・1on1・チーム編成・業務アサインの参考に限定してください
- **開示範囲を先に決める。** 推奨は「全順位は本人のみ／Top5は本人同意のうえチーム共有」
- **同意とデータ保管を先に決める。** フォーム冒頭に用途を明記していますが、回答シートの閲覧権限と保管期間は社内ルールに沿って定めてください
- **年1回の再受検を前提にしています。** 結果は固定的な特性ではなく、その時点の傾向として扱ってください

---

## 6. カスタマイズ

テーマや設問は `src/data.js` が唯一の定義元です。ここを直して `node tools/build.js` を実行すると、
`report.html`・`form-generator.gs`・`docs/` がまとめて再生成されます。

| 変えたいもの | 触る場所 |
|---|---|
| テーマの定義・向く仕事・1on1の問い | `src/data.js` の `THEMES` |
| 設問の文言 | `src/data.js` の `ITEMS`（変更後はフォームを作り直す） |
| Top5 → Top3、全社比較の最低人数 | `src/scoring.js` の `SCORING` |
| 画面の見た目・レポートの構成 | `src/report.template.html` |

```bash
node tools/build.js    # 配布物と docs を再生成
node tools/verify.js   # 採点ロジックとパーサのテスト（11項目）
```

設問文を変えると既存フォームの見出しと一致しなくなり、貼り付け時に「見つからなかった設問が◯問」と表示されます。
誤った採点を防ぐための挙動なので、フォームを作り直してください。

## 7. ファイル構成

```
strengths/
├── report.html            ← 回答を貼るとレポートが出る（配布物）
├── form-generator.gs      ← Googleフォームを1回で作る（配布物）
├── docs/
│   ├── theme-dictionary.md  12テーマの定義（自動生成）
│   └── items.md             全60問（自動生成）
├── sample/
│   └── sample-responses.tsv 動作確認用の合成データ（架空の12人）
├── src/                   ← 編集するのはここ
│   ├── data.js              テーマ辞書・設問・出題順
│   ├── scoring.js           採点エンジン
│   ├── csv.js               CSV/TSVパーサ
│   ├── report.template.html レポート画面のテンプレート
│   └── form-generator.template.gs
└── tools/
    ├── build.js             src/ → 配布物を生成
    └── verify.js            テスト
```
