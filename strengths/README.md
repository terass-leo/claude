# 強み診断（Strengths Survey）

Google Forms → Spreadsheet → GAS採点 → Claude API による個人レポート生成までを、
Apps Script 一式で完結させる社内向け強み診断です。

- **測るもの**: 12テーマ（4領域 × 3）を60問で測定
- **所要時間**: 回答は約10分
- **1人あたりの生成コスト**: Claude API で数円程度（レポート1本 = 1リクエスト）
- **採点は決定論的**: 順位計算にLLMは関与しないため、同じ回答からは必ず同じ順位が出る

---

## 1. 何がどう出るか

| 段階 | 出力 |
|---|---|
| 回答 | フォームの回答が `フォームの回答 1` シートに蓄積 |
| 採点 | `結果` シートに テーマ別素点 / 個人内Zスコア / 12テーマの順位 / Top5 / 回答品質フラグ |
| レポート | Google ドキュメント（Drive の「強み診断レポート」フォルダ）にレポート本文＋順位表、URLは `結果` シートに記録 |

生成されるレポートの構成は次の7ブロックです。

1. あなたの強み トップ5（各150〜200字）
2. 強みの組み合わせが生む持ち味
3. 活かしどころ（向いている仕事の型 × 5）
4. 強みが出すぎたときの注意点（× 3）
5. 相対的に控えめな面との付き合い方
6. アサイン担当者向けメモ（任せると伸びる仕事／補完が要る場面／1on1で確かめたい問い）
7. 12テーマの順位表と注意書き

## 2. セットアップ手順

### ステップ1: スプレッドシートとスクリプトを用意する

1. 新しい Google スプレッドシートを作成する（このシートが以降の母艦になる）
2. 「拡張機能 → Apps Script」を開く
3. `gas/` 配下の `.gs` ファイルを同じ名前でスクリプトエディタに作成し、内容を貼り付ける
   - `00_Config.gs` `01_Themes.gs` `02_Items.gs` `03_Scoring.gs` `04_Setup.gs` `05_Report.gs` `06_Main.gs` `07_Test.gs`
   - `appsscript.json` はエディタの「プロジェクトの設定 → 『appsscript.json』マニフェスト ファイルをエディタで表示する」をオンにすると編集できる

> `clasp` を使う場合は `gas/` をそのまま `clasp push` すれば同じ状態になります。

### ステップ2: APIキーを登録する

Apps Script エディタの「プロジェクトの設定 → スクリプト プロパティ」で追加します。

| プロパティ | 値 |
|---|---|
| `ANTHROPIC_API_KEY` | Anthropic Console で発行したAPIキー |

APIキーはコードに書かず、必ずスクリプトプロパティに置いてください。

### ステップ3: 初期セットアップを実行する

1. スプレッドシートを再読み込みすると、メニューに **「強み診断」** が出る
2. **「① 初期セットアップ（フォーム作成）」** を実行し、権限を承認する
   - 60問のフォームが自動生成され、回答先がこのシートに紐づく
   - `設問マスタ` / `結果` / `実行ログ` シートが作られる
   - 回答受信時の自動採点トリガーが登録される
3. 完了ダイアログに出るフォームURLを配布する

### ステップ4: 動作確認

- **「セルフテスト（API不要）」** — 設問マスタと採点ロジックの整合性を10項目チェック
- **「Claude API 接続テスト」** — APIキーと疎通の確認（数円未満）
- 自分でフォームに1件回答し、`結果` シートに行が増えてレポートURLが入ることを確認

## 3. 日常運用

| やりたいこと | 操作 |
|---|---|
| 回答が来たら自動で処理 | 何もしなくてよい（送信トリガーで自動実行） |
| トリガーが失敗した分を拾う | メニュー「② 未処理の回答を採点・レポート生成」 |
| レポート文だけ作り直す | `結果` シートで対象行を選択 →「選択行のレポートを作り直す」 |
| 全社の中での位置を見る | 「全社比較シートを更新する」（回答者10人以上で有効） |
| エラーを確認する | `実行ログ` シート、および `結果` シートの「状態」列 |

回答が大量に溜まっている場合、1回の実行はGASの6分制限手前で自動的に中断します。
`実行ログ` にその旨が残るので、「②」をもう一度実行してください。

## 4. 設計の考え方

### 強みは「個人内の相対順位」で決める

全項目に高く答える人と低く答える人がいるため、テーマの素点をそのまま比べても
「回答スタイルの差」を測ってしまいます。そこで12テーマの素点を **本人の平均・標準偏差で標準化** し、
その人の中での相対順位として Top5 を決めています（`結果` シートのZ列）。

全社の中での位置を見たいときは、別軸の「全社比較」シート（コホートZ）を使います。
回答者が10人（`CONFIG.NORM_MIN_N`）に満たないうちは、母数不足のため出力しません。

### 逆転項目で回答の質を見る

各テーマに1問ずつ逆転項目を置いています。「すべて5」のような読み飛ばし回答は、
順項目と逆転項目の食い違いとして検出され、`回答品質フラグ` に記録されます。
フラグが立った結果は、レポート側でも断定を弱める指示がClaudeに渡ります。

### LLMの役割を「文章化」に限定する

順位・スコアはGASが計算し、Claudeには確定済みの順位とテーマ辞書だけを渡します。
Claudeには「与えられた辞書と順位以外の事実を創作しない」「数値を本文に書かない」
「下位テーマを弱みと断定しない」を厳守させています。採点にLLMを使わないため、
再現性と説明責任が保てます。

## 5. 運用上のルール（重要）

- **人事評価・選考の判断材料には使わない。** 妥当性検証が済んでいない自己申告データであり、
  評価に使うと納得感と信頼を損ないます。用途は育成・1on1・チーム編成・業務アサインの参考に限定してください。
- **開示範囲を先に決める。** 推奨は「全順位は本人のみ／Top5は本人同意のうえチーム共有」。
  `CONFIG.SHARE_REPORT_WITH_RESPONDENT` を `true` にすると、レポートDocに本人の閲覧権限を自動付与します。
- **同意とデータ保管を先に決める。** フォーム冒頭の説明文（`CONFIG.FORM_DESCRIPTION`）に用途を明記済みですが、
  社内の個人情報取扱いルールに沿って保管期間と管理者を定めてください。
- **年1回の再受検を前提に設計しています。** 結果は固定的な特性ではなく、その時点の傾向として扱ってください。

## 6. カスタマイズ

| 変えたいもの | 触る場所 |
|---|---|
| テーマの定義・向いている仕事 | `gas/01_Themes.gs` |
| 設問の文言・追加・削除 | `gas/02_Items.gs`（変更後は必ずフォームを作り直す） |
| Top5 → Top3 などの表示数 | `CONFIG.TOP_N` / `CONFIG.BOTTOM_N` |
| レポートの構成・トーン | `gas/05_Report.gs` の `buildSystemPrompt_` / `buildUserPrompt_` |
| レポート品質とコストのバランス | `CONFIG.EFFORT`（`medium` → `high` で文章の作り込みが上がる） |

設問文を編集した場合、既存フォームの設問文と `ITEMS` の対応が取れなくなるため、
採点時に「回答シートの見出しと設問マスタが一致しません」というエラーで停止します。
これは誤った採点を防ぐための意図的な設計です。フォームを作り直してください。

`docs/` 配下の Markdown は `.gs` のデータから生成しています。定義や設問を変えたら再生成してください。

```bash
node tools/gen-docs.js   # docs/theme-dictionary.md と docs/items.md を更新
node tools/verify.js     # 採点ロジックのセルフテストをローカルで実行
```

## 7. ファイル構成

```
strengths/
├── gas/                    Apps Script 本体（そのまま貼り付け／clasp push）
│   ├── appsscript.json     マニフェスト（実行環境とスコープ）
│   ├── 00_Config.gs        全体設定（APIモデル、シート名、採点閾値）
│   ├── 01_Themes.gs        12テーマの辞書
│   ├── 02_Items.gs         60設問と出題順
│   ├── 03_Scoring.gs       採点エンジン（決定論的）
│   ├── 04_Setup.gs         フォーム生成・シート整備・トリガー登録
│   ├── 05_Report.gs        Claude API 呼び出しとDoc出力
│   ├── 06_Main.gs          実行フローとメニュー
│   └── 07_Test.gs          セルフテスト
├── docs/
│   ├── theme-dictionary.md 12テーマの定義（.gsから自動生成）
│   └── items.md            全60設問（.gsから自動生成）
└── tools/
    ├── verify.js           採点ロジックのローカル検証
    └── gen-docs.js         docs/ の再生成
```
