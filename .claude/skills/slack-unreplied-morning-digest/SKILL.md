# Slack 返信忘れ 朝ダイジェスト

毎朝8時（JST）に、Leo宛の未返信メッセージを洗い出して**Leo自身のDM**（`channel_id: U02GDKKU5UH`）へ
1メッセージで投稿する。ゴールは「朝イチで開けば、今日返すべきスレッドとその優先順位が分かる」状態を作ること。

## 設計思想（ここを外すと価値が消える）

1. **取りこぼしより誤検出の方がマシ**。判定に迷ったものは未返信側に倒し、注記を付ける。
2. **繰越こそが本質**。1日で消える一覧は「返信忘れ」を防げない。前回未返信だったものが今日も未返信なら、
   放置日数を付けて必ず再掲する。放置が長いものほど上に出す。
3. **前回投稿がステート**。DBは持たない。自分のDMに投稿した前回ダイジェストを読み直して、
   「どこから拾うか」「何を繰り越すか」を決める。
4. **重複投稿は事故**。同じ日に2通投げない。Step 1のガードを必ず最初に通す。

## 前提

- Slackコネクタ必須。Leoのuser_id: `U02GDKKU5UH`（自分宛DMのchannel_idとしてもこの値を使う）。
- DM・プライベートチャンネルも対象なので `slack_search_public_and_private` を使う
  （このジョブの起動自体が同意とみなす。確認は不要）。
- 現在時刻は必ず `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M %a'` で取得する。日付を推測しない。
- Unixタイムスタンプは `TZ=Asia/Tokyo date -d 'YYYY-MM-DD HH:MM:SS' +%s` で計算する。

## 手順

### Step 1: 重複ガード ＋ 前回ダイジェストの特定（必須・最初に実行）

`slack_read_channel`（channel_id: `U02GDKKU5UH`, limit: `30`, response_format: `detailed`）で自分のDMを読む。

- 本文が `【` で始まり `未返信ダイジェスト` を含むメッセージが、このジョブの過去投稿。
- **同じ日付（JST）の投稿がすでにある場合は、何もせず即終了する。** Slackにも報告にも何も出さない。
- 最新のダイジェスト投稿を「前回投稿」とし、その **ts（=収集起点）** と **本文中の全パーマリンク** を控える。
- 前回投稿が見つからない、または7日以上前の場合は、収集起点を **現在時刻の72時間前** にフォールバックする
  （初回起動・長期停止からの復帰時。この場合は出力冒頭に「初回/復帰実行のため直近72時間を対象」と注記）。

### Step 2: 収集範囲の確定

- 起点 = Step 1で決めた前回投稿ts（フォールバック時は72時間前）
- 終点 = 現在時刻
- 月曜の実行では起点が金曜朝になるため、自然と土日分を含む。**曜日で場合分けしない。**

### Step 3: 収集（3系統・すべてページネーションを最後まで回す）

#### (a) 個別メンション

`slack_search_public_and_private`
- query: `<@U02GDKKU5UH> -from:me`
- after / before: Step 2のUnixタイムスタンプ（inclusive）
- sort: `timestamp`, sort_dir: `asc`, include_context: `false`, response_format: `detailed`
- channel_types: 既定（全種別）
- `pagination_info` にcursorがある限り繰り返す。**件数が多くても途中で打ち切らない。**

#### (b) メンションなしのDM・グループDM

`slack_search_public_and_private`
- query: `to:<@U02GDKKU5UH> -from:me`
- channel_types: `im,mpim`
- after / before / sort / sort_dir は (a) と同じ
- (a) で拾った ts と重複するものは除外する。
- アプリ・bot発（freee / Google Calendar / Slackbot / Notion 等）は本編から外し、
  **「本人の作業が要るもの」だけ** を後述の bot枠に1〜2行で残す（例: freee勤怠エラー＝打刻修正が必要）。
  単なる通知・リマインドは捨てる。

#### (c) 繰越候補

Step 1で控えた前回投稿の「未返信」「繰越」セクションのパーマリンクを全件。

各メッセージについて **Channel名 / Channel ID / 送信者 / 時刻(JST) / message_ts / Permalink / 本文要旨** を控える。

### Step 4: 返信判定

各対象について:

1. **スレッドrootの特定**: Permalinkに `thread_ts=` があればその値がroot。なければ自身のtsがroot。
2. `slack_read_thread`（channel_id + root ts, response_format: `detailed`）でスレッド全体を取得。
3. **DM・グループDM（im / mpim）は必ず `slack_read_channel` でも判定する。**
   これらのチャンネルでは返信をスレッドではなく**チャンネル直下**で返すのが普通で、
   スレッドだけ見ると「返信済みなのに未返信」と誤検出する（実測で発生済み）。
   対象メッセージのtsを `oldest` に指定して以降の発言を読み、`U02GDKKU5UH` 発のものがあれば返信済み。
   ただしその後さらに相手から新しい問いかけが来ていれば、**その新しいメッセージを別件として未返信に立てる**。
4. **返信済み**: スレッド内（DM系はチャンネル直下も）に `U02GDKKU5UH` 発で、
   対象メッセージのtsより**後**のものがある → 一覧から落とす。
5. **リアクションのみ**: 返信はないが対象メッセージのreactionsに `U02GDKKU5UH` が含まれる → 別枠。
   返信済み扱いにはしない（絵文字で完結してよいかはLeoが判断する）。
6. どちらでもない → **未返信**。
7. スレッドが取得できない（権限・削除等）→ 落とさず「判定不能」として未返信側に残す。
8. 相手の発言が「承知しました」「すぐ提出します」「セット済みです」等の**応答・報告で完結している**なら、
   未返信ではあっても要対応ではない。共有系に落とす。

**統合・除外ルール:**
- 同一スレッドで複数回メンションされていたら1件に統合し、**最も古いメンション時刻**で放置日数を計算する
  （新しい方で計算すると放置が短く見えてしまう）。
- 宛先が別人でLeoはCcのものも**落とさない**。ステータスとは別に「Cc」と注記する。
- 繰越分で返信済みになっていたものは静かに落とす。「返信済みになりました」の報告は不要。

### Step 5: 分類と優先順位

未返信を以下に振り分ける。判断はメッセージ本文の**依頼形**（〜でしょうか／ご確認ください／〜まで）と
**期限の有無**で行う。

| 区分 | 条件 |
|---|---|
| **要対応** | 質問・依頼・承認待ち・期限付き。返信しないと相手が止まる |
| **リアクション済み／共有系** | 報告・共有・FYI。絵文字で足りる可能性が高い |
| **Cc・FYI** | 宛先が別人。Leoの返信は基本不要 |

**要対応の並び順**（上から）:
1. **期限が今日・明日のもの**（相手や候補者の予定が今日明日で動く。放置日数より優先する）
2. 繰越（放置日数の長い順）
3. 新規（古い順）

期限付きには `⏰ M/D期限` を付ける。

役員・経営陣（CEO/COO/CFO）宛や、社外・候補者が絡むものは同条件なら上に置く。

### Step 6: 投稿

`slack_send_message`（channel_id: `U02GDKKU5UH`）で**1メッセージ**投稿する。

```
【M/D(曜) 朝 未返信ダイジェスト】
要対応 N件（うち繰越 X件）／ 共有・リアクション Y件 ／ Cc・FYI Z件
対象範囲: M/D HH:MM 〜 M/D HH:MM

■ 要対応
1. 🔴 [3日放置] #チャンネル名｜送信者｜M/D HH:MM
   要旨: 依頼・質問の中身を1文。返信の要否が判断できるように
   → [スレッドを開く](パーマリンク)
2. #チャンネル名｜送信者｜M/D HH:MM
   要旨: ...
   → [スレッドを開く](パーマリンク)

■ リアクションのみ／共有系（返信不要の可能性）
・#チャンネル名｜送信者｜HH:MM｜要旨 → [開く](パーマリンク)

■ Cc・FYI
（1〜2行に圧縮。件名の羅列でよい。パーマリンク不要）

■ 要対応（Slack返信以外）
・freee勤怠エラー: 8/3 出退勤未入力 → 本人の打刻修正が必要

※検出対象は個別メンション＋DM。スレッド外（チャンネル直下の別メッセージ）での返信は検出できません。
```

フォーマット規約:

- **URLは必ず `[テキスト](URL)` のマークダウンリンクにする。裸URLは禁止**
  （裸URLの直後に改行＋本文が続くとSlackのリンク変換が壊れる既知の不具合がある）。
- 太字は `**`（`slack_send_message` が標準マークダウンをSlack記法に変換する）。
- **Markdownのテーブル記法は使わない**（Slackで本文ごと消える）。
- 繰越には `🔴 [N日放置]` を付ける。3日以上は必ず🔴。
- 要旨は1文。DM・プライベート由来の機微情報（個人の評価・報酬・労務案件）は
  **要旨レベルに留め、本文を転記しない**。
- 全体で長くなりすぎたら、要対応は全件残し、共有系とCcを削って調整する。**要対応は絶対に省略しない。**

**要対応ゼロの場合**は一覧を作らず、1行で投稿する:

```
【M/D(曜) 朝 未返信ダイジェスト】要対応の未返信はありません（対象 N件はすべて返信済み）。
```

（0件でも投稿する。「今日は無風」という情報自体に価値があり、無言だとジョブが落ちたのか判別できない）

### Step 7: 投稿後の検証

`slack_read_channel`（channel_id: `U02GDKKU5UH`, limit: `1`）で自分の投稿を読み直す。
リンクが `<URL|テキスト>` に正しく変換されているか、本文が途中で壊れていないかを確認する。
壊れていたら修正版を投稿し直す（壊れた方は残してよい）。

完了したら結果を1〜2行で報告して終了する。

## 失敗時の挙動

- Slack検索がエラー・0件を返した場合は、クエリを変えず**最大3回リトライ**する。
  それでも取得できなければ、DMに「本日は検索APIエラーのため取得できませんでした」とだけ投稿する
  （黙って終了しない。無言＝未返信ゼロと誤解される）。
- スレッド読み取りが一部失敗しても、成功した分で投稿する。失敗分は「判定不能」として残す。
- 投稿自体が失敗したらリトライし、それでも駄目ならエラー内容を報告して終了する。

## 品質基準

- **勝手に返信・下書きしない。** このジョブの出力は一覧のみ。
- **投稿先は `U02GDKKU5UH`（自分のDM）のみ。** 他人・チャンネルへは絶対に投稿しない。
- パーマリンクは検索結果のPermalinkをそのまま使う。自前で組み立てない
  （enterprise環境のためドメイン形式が特殊）。
- 対象範囲外（起点より前）のメッセージを混ぜない。ただし繰越分はこの限りではない。
