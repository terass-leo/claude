# grp_hqhr-question AI返信ドラフト自動投稿

## 概要

`#grp_hqhr-question`（channel_id: `C06ELPXMK09`）は本部人事（HQHR）への問い合わせチャンネル。
起票はSlackワークフロー経由で行われ、**質問本文はチャンネルには表示されず**（個人情報保護のため）、
Bot が「〇〇に関する質問・相談を受け付けました！」という受付メッセージだけをチャンネルに投稿する。
質問本文は転記スプレッドシート「grp_hqhr-questionタスク管理」に記録される。

このスキルは、未回答の起票を検出し、質問本文をスプシから特定し、ナレッジソースに基づく
**返信ドラフト（HQHR確認用）** を当該スレッドに投稿する。**最終回答はあくまで人間（HQHR）が行う。**

## 手順

### 1. 新規起票の検出

1. `slack_read_channel`（channel_id: `C06ELPXMK09`, limit: 50）で直近メッセージを取得。
2. **直近72時間以内**のBot投稿（受付メッセージ「〜受け付けました！」形式）を起票として抽出。
   人間の直接投稿（ワークフローを介さない質問）も対象にしてよいが、その場合質問本文はメッセージ自体にある。
3. 各起票について `slack_read_thread` でスレッドを確認し、以下のいずれかに該当したら**スキップ**：
   - スレッドに人間（Bot以外）の返信が既にある（＝HQHRが対応済み・対応中）
   - スレッドに「AI返信ドラフト」を含む投稿が既にある（＝二重投稿防止）
   - 親メッセージに `済み` リアクションがある

### 2. 質問本文の特定（スプシ突合）

**重要: Driveの `read_file_content` は行数の多いシートで途中までしか返さないため使わない。**
必ず xlsx をダウンロードしてローカル解析すること：

1. `download_file_content`（fileId: `1LWNQ_Y_DlOU2BVvbN875B2xQA1a6pLgaYZiLt8Pz1WQ`,
   exportMimeType: `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`）を実行。
   結果はbase64。大きいのでツール結果はファイルに保存される想定。
2. Pythonで解凍・解析（openpyxlが無ければ `pip install openpyxl`）：

```python
import json, base64, openpyxl
d = json.load(open(SAVED_TOOL_RESULT_PATH))
open('hqhr.xlsx','wb').write(base64.b64decode(d['content']))
wb = openpyxl.load_workbook('hqhr.xlsx')
rows = list(wb['勤怠'].iter_rows(values_only=True))  # 対象シート
```

3. 行の突合ルール：
   - シートの `日時` 列は **UTC**（Slack表示はJST＝UTC+9）。文字列の場合は
     `%b %d, %Y, %I:%M:%S %p` または `%b %d, %Y, %I:%M %p` でパース。
   - **Slack起票メッセージのts（epoch秒）との差が±15分以内** かつ
     **投稿者名（`@名前` 列）がSlackでメンションされた相談者と一致**する行を採用。
     （スプシ日時はSlack投稿の数分前になることが多い）
   - 複数候補があれば時刻が最も近い行。見つからなければその起票はスキップし、サマリーに記録。
4. 質問本文はシートにより `相談・質問内容` 列または `詳細` 列（勤怠・住民税等はカテゴリ＋詳細の2段構成）。
   `期日`（希望回答期日）も取得する。

### 3. ナレッジ収集と回答検討

質問カテゴリに応じて以下を参照し、回答根拠を集める：

- **FAQ（Notion `2802fabcb4d080138d9aefbb7d6971b3`）**: 全カテゴリでまず必ず確認。
  勤怠（振休・法定休日早見表・有休）、住民税切替、給与明細・口座、HiManager/HRBrainログイン、
  健保・健診、福利厚生（Housing Plan / Best Productivity）、副業などの定番回答が載っている。
- **勤怠マニュアル（Notion `e38d1a8909614787923978daa5e9ca44`）**: 勤怠カテゴリの質問はこちらも確認。
- **給与・労務系マニュアル（Notion `33cec79f377f484396ee7964a84ee91c`）**: 給与・住所変更・通勤費・源泉徴収票など。
- **過去の類似対応**: ダウンロード済みxlsxの同一シートで類似質問の過去行を探す。
  さらに `slack_search_public`（`in:#grp_hqhr-question キーワード`）で過去スレッドの実回答を確認すると精度が上がる。

回答方針：
- 根拠が明確な場合のみ断定する。根拠が弱い場合はドラフト内に `⚠要確認` として明示し、
  推測で断定しない（誤回答が最大のリスク）。
- 手続き案内はFAQ/マニュアルの該当NotionページのURLを添える。
- 依頼系（書類記入・口座変更・システム再設定など）は「回答」ではなく
  「受領確認＋対応の流れ＋所要日数」のドラフトにする（書類記入は最短2〜3営業日かかる旨など）。

### 4. ドラフト投稿

`slack_send_message`（channel_id: `C06ELPXMK09`, thread_ts: 起票メッセージのts）で投稿。

**フォーマット（厳守）：**

```
:robot_face: **AI返信ドラフト（HQHR確認用）**
※AIによる自動生成の下書きです。HQHRメンバーが内容を確認・編集のうえ正式回答をお願いします。

**▼質問の要点**（希望期日: YYYY/MM/DD）
（1〜2行。センシティブな情報＝金額・傷病名・家族事情などは伏せる）

**▼推奨返信ドラフト**
> ＠（相談者名）
> お問い合わせありがとうございます:herb:
> （回答本文。TERASSのHQHRの文体：丁寧・簡潔・結論から）
> どうぞよろしくお願いいたします。

**▼根拠・参考**
- （FAQ/マニュアルの該当箇所タイトルとリンク、過去の類似スレッドリンク）
- 確信度: 高／中／低（低の場合は ⚠要確認 ポイントを箇条書き）
```

投稿ルール：
- **相談者へのSlackメンション（`<@U...>`）は絶対に使わない**。未確認の回答が本人に通知されるのを防ぐため、
  引用ドラフト内の宛先は全角＠＋表示名のプレーンテキストで書く（HQHRがコピペ時にメンションへ直す）。
- URLは必ず `[タイトル](URL)` のマークダウンリンクで書く（裸URL禁止）。
- 実際の回答者の文体に合わせる：冒頭「お問い合わせありがとうございます:herb:」、
  結び「どうぞよろしくお願いいたします。」、結論ファースト、1回答400字以内目安。
- 質問がセンシティブ（給与額・評価・傷病・家族等）な場合は、要点を最小限にし、
  ドラフト末尾に「※内容がセンシティブなためDMでの回答を推奨」と付記する。
- 投稿後に `slack_read_thread` で自分の投稿を読み直し、リンク・体裁が壊れていないか確認する。

### 5. 実行サマリー

処理完了後、以下を簡潔にまとめて終了する（Slackには投稿しない）：
- 検出した起票数／ドラフト投稿数／スキップ数（理由別：回答済み・ドラフト済み・スプシ突合不可など）
- 投稿した各ドラフトのスレッドリンク

### 6. 失敗時の挙動

- スプシのダウンロードに失敗したらリトライ（最大3回）。それでも失敗したら起票検出結果だけサマリーに残して終了。
- Slack投稿に失敗したらリトライし、失敗が続いたらその起票をスキップして次へ。
- 1件の失敗で全体を止めない。
