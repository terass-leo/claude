# AI×HR ナレッジ デイリー投稿

Slackの `#grp_ai-hr-knowledge`（channel_id: `C0BKW0AJBQV`）に、AI×HR（人事）領域の
①YouTube動画1本 ②noteのバズ記事1本 を、それぞれ【要約】【TERASS活用のヒント】付きで投稿する。

## 前提・制約

- youtube.com / note.com のページは WebFetch では 403 になる（bot保護）。**情報収集はすべて WebSearch で行う**こと。
- コンテナからの curl も外部一般サイトへはネットワークポリシーで403になる。curlでの収集は試みない。
- Slack投稿は `mcp__Slack__slack_send_message` を使う（Slackコネクタ必須）。

## 手順

### 1. 重複チェック（過去投稿の把握）

`slack_read_channel`（channel_id: `C0BKW0AJBQV`, limit: 50）で直近の投稿を読み、
**過去に紹介済みのYouTube URL / note URLを控える。同じURLは二度と投稿しない。**

### 2. YouTube動画の選定

WebSearch を複数クエリで実行し、候補を集める：

- `AI 人事 HR site:youtube.com`（allowed_domains: ["youtube.com", "www.youtube.com"]）
- `生成AI 人事 活用 site:youtube.com`
- `AI 採用 HR YouTube 動画 <今年>年` など、日によってクエリを変えて鮮度を出す

選定基準（優先順）：
1. 未投稿であること（手順1のリストと突合）
2. 公開が新しい・話題性がある（検索結果の日付情報を参考に）
3. 人事実務（採用・評価・労務・育成・組織開発）への示唆が具体的

内容が検索スニペットだけで足りない場合は、動画タイトルでもう一度 WebSearch して
解説記事・書き起こし等から内容を補強する。

### 3. note記事の選定（★品質がこのスキルの勝負どころ）

**前提**：スキ数は機械的に取得できない（note検索API・記事ページとも WebFetch/curl 双方403）。
したがって「スキ数で並べる」のではなく、**下記のクエリ戦略と品質ゲートで一次情報を狙い撃つ**。

#### 3-1. クエリ戦略：一般語で引くな、事象で引け

一般語クエリ（`AI 人事 活用 site:note.com` 等）は**ベンダーのSEO記事しか返らない**（実測済み）。
必ず以下の「事象ベース」で引くこと：

1. **まず今週のAI×HRの"事象"を掴む**（note縛りなしの通常WebSearchで）
   例：`AI 人事 ニュース 2026年7月`、`HR AI 人事制度 発表 話題`
   → 具体的な事象（企業の人事発表・組織変更・新制度・調査結果・法改正など）を1〜2個特定する
2. **その事象の固有名詞でnoteを引く**
   例：`メルカリ CHRO CAIO note`、`LINEヤフー 人事 AI note`、`経団連 AI 報告書 人事 note`
   → 実名の実務家が独立に書いた記事が並ぶ。**同じ事象を複数人が書いていること自体が反響の代理指標**
3. **肩書き・役割ベースで引く**
   例：`CHRO 人事責任者 AI 組織 note`、`人事 マネージャー AI 導入 振り返り note`
4. **一次体験の言い回しで引く**
   `やってみた`／`わかったこと`／`2か月`／`失敗`／`参加レポート`／`振り返り` ＋ 具体的な会社名・職種
5. **良質な書き手の新作を直接見に行く**（下の 3-4 ホワイトリスト）

#### 3-2. 除外ゲート（これに当たったら候補から落とす）

- **タイトルパターン**：`【20XX年最新】`／`【2026年版】`／`〜選`／`完全ガイド`／`おすすめ`／
  `メリット・デメリット`／`導入手順`／`徹底解説`／`無料配布`／`プロンプト◯選`
- **著者パターン**：AI開発・受託開発会社、HRTechベンダー、転職メディアの法人アカウントによる
  集客目的の記事（例：`株式会社◯◯`／`◯◯ラボ`／`◯◯【公式】` 名義の一般論まとめ）
- **例外（拾ってよい）**：ベンダー・コンサルでも**自社で実験・検証して一次データを出している**記事は可
  （例：グローセンパートナーの「生成AIで人事制度はどこまで構築できるか」検証シリーズ）

#### 3-3. 採用シグナル（優先順）

1. **一次情報性** … 書き手自身がやった／見た／決めたことが書かれている（実践記・導入の振り返り・
   参加レポート・当事者による解説）。伝聞の一般論は弱い
2. **反響の代理指標** … 同じ事象を複数の書き手が独立に書いている／他媒体（Wantedly・X・
   まとめ記事・ニュースレター）に転載・引用されている。**記事タイトルや事象名で再検索して確認する**
3. **書き手の実体** … 実名＋所属＋肩書きが明示され、人事・経営の実務家または研究者である
4. **具体性** … 固有名詞の企業名・実数値・意思決定の背景が入っている

#### 3-4. 良質な書き手ホワイトリスト（見つけ次第ここに追記して育てる）

- Ryosuke Fujiwara（Gaudiy 人事）… AIエージェントとの実践記
- kazu / inouepascal … HR・採用・HRTechの月次定点観測
- グローセンパートナー（growthen）… 生成AI×人事制度の一次検証シリーズ
- 井上和幸（経営者JP）／池松潤／田中研之輔（法政大）／四栗崇 … CHRO・組織論の実務家・研究者
- ハイマネージャー（kengomori）… HR領域の海外動向

#### 3-5. 選定プロセス（1本目を採用してはいけない）

- 候補を**最低4本**集める（3-1 の複数クエリを必ず併用）
- 各候補に 3-2 の除外ゲートを当て、残りを 3-3 の4シグナルで ○△× 評価する
- **最上位を1本選ぶ。候補が全滅（全部SEO記事）なら、クエリを事象ベースに変えて最低3回再探索する**
- それでも基準を満たすものが無い日は、無理にnoteを出さず「本日はYouTubeのみ」とする
  （質の低い記事を出すより見送る方がチャンネルの価値を守れる）

なお YouTube 側も同じ考え方が効く（一般語より、対談番組・実映像・当事者登壇のものを優先）。

### 4. サマリー作成

各コンテンツについて日本語で作成する：

- **【要約】** … 3〜4文。何を主張・紹介している動画/記事か、具体的な数字や事例があれば含める。
  - **1文目で「誰が書いた/話しているか」（実名・所属・立場）を明示する**（一次情報性が読み手に伝わる）
  - 可能なら「なぜ今これが話題なのか」の文脈を1文入れる（例：どの企業の人事発表を受けた議論か）
- **【TERASS活用のヒント】** … 2〜3文。TERASSの文脈に引き付ける：
  - TERASSは不動産エージェント向けプラットフォーム企業（Terass Agent約1,500名規模、少数精鋭の本部組織）
  - HR Divの実務：本部採用（HERP）、半期評価（HiManager）、労務（freee人事労務）、エージェント向けサポート、1on1文化
  - 「明日から試せる」レベルの具体的な適用アイデアに落とす

### 5. Slack投稿

`slack_send_message` で `C0BKW0AJBQV` に1メッセージで投稿する。フォーマット：

```
:sunny: **AI×HRナレッジ便り** | YYYY/MM/DD（曜）

:tv: **今日のYouTube**
[動画タイトル](URL)

【要約】
（3〜4文）

【TERASS活用のヒント】
（2〜3文）

:memo: **今日のnoteバズ記事**
[記事タイトル（著者名）](URL)

【要約】
（3〜4文）

【TERASS活用のヒント】
（2〜3文）
```

- **URLは必ずマークダウンリンク `[タイトル](URL)` で置く。裸のURLは禁止**
  （裸URLの直後に改行＋本文が続くと、Slackのリンク変換が壊れて本文がリンク記法に巻き込まれ、リンクが開けなくなる既知の不具合がある）
- 太字は `**` を使う（slack_send_message は標準マークダウンをSlack記法に変換する）
- 全体で読み切れる分量（各セクション400字以内目安）に収める

#### 太字が壊れる条件（実測4件から確定。過去2回、誤った条件を書いて再発させた）

**閉じ `**` の直前が記号だと、閉じ記号として認識されない。**
すると次の `**` までが1つの太字範囲になり、**段落まるごと太字になる**（または `**` が literal 表示になる）。

実測した失敗と成功：

| | 例 | 閉じ `**` の直前 | 結果 |
|---|---|---|---|
| NG | `**〜16%**でした` | `%` | 壊れる |
| NG | `**〜63.6%**、課長は` | `%` | 壊れる |
| NG | `**"〜整える"**という` | `"` | 壊れる |
| OK | `**優秀なだけの人はAIに淘汰される**という` | `る` | 正常 |
| OK | `**チームを0.7倍にする人**という` | `人` | 正常 |
| OK | `**AIが使えない職場だから辞める**、` | `る` | 正常 |

閉じ記号の**直後**が何であるか（和文でも句読点でも）は関係ない。効くのは**直前の1文字**。

原則：**閉じ `**` の直前は必ず仮名・漢字・英字にする**。
数値や引用符で終わる強調は、太字範囲に語を足して逃がす
（`**〜63.6%**、` → `**〜63.6%に達した**、` ／ `**"〜"**` → `"**〜**"`）。

**送信前チェック（必ず本文を目視で走査してから `slack_send_message` を呼ぶ）**

1. すべての閉じ `**` の直前1文字を見る。`%` `"` `）` `」` などの記号なら、
   語を足して仮名・漢字・英字で終わるように直す
2. 裸のURLが1つも無いか（すべて `[タイトル](URL)` になっているか）
3. 見出し記号（`:sunny:` `:tv:` `:memo:`）と日付が揃っているか

- 投稿後に `slack_read_channel`（limit: 1）で自分の投稿を読み直し、リンクが `<URL|タイトル>` 形式に正しく変換されているか・本文が壊れていないかを確認する。
  - **リンクが壊れている／本文がリンク記法に巻き込まれている場合は修正版を投稿し直す**
  - 太字マーカーが1〜2箇所 literal 表示されているだけなら、重複投稿でチャンネルを汚す方が害が大きいので投稿し直さず、次回の送信前チェックで防ぐ

### 6. 失敗時の挙動

- 検索で新規コンテンツが見つからない場合は、クエリを変えて最低3回は再検索する
- それでもYouTube/noteの片方しか見つからない場合は、見つかった方だけでも投稿し、
  本文中に「本日は◯◯のみ」と一言添える
- Slack投稿自体が失敗した場合はリトライし、それでも失敗したらエラー内容を残して終了する
