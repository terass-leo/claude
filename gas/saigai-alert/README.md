# TERASS 災害アラート（Google Apps Script）

気象庁の公開防災情報を5分ごとに取得し、社員の現住所と突合して、該当社員がいる場合に
Slack `#p_saigai` へ自動通知する仕組み。**Claudeを介さず単体で動く。**

```
気象庁 防災情報JSON  ──5分ごと──▶  Google Apps Script  ──▶  Slack #p_saigai
（地震・津波）                      ｜
                                    ▼
                          社員住所マスタ（スプレッドシート）
```

## 構成ファイル

| ファイル | 内容 |
|---|---|
| `Code.gs` | 本体。取得・突合・通知・重複防止のすべて |
| `appsscript.json` | GASプロジェクト設定（タイムゾーン Asia/Tokyo） |
| `test/match.test.js` | 突合ロジックの検証（`node gas/saigai-alert/test/match.test.js`） |

## 使うデータ

**災害情報**（気象庁 防災情報。認証不要・利用規約は[こちら](https://www.jma.go.jp/jma/kishou/info/coment.html)）

- 地震リスト `https://www.jma.go.jp/bosai/quake/data/list.json`
- 地震詳細（市区町村別震度）`https://www.jma.go.jp/bosai/quake/data/{list の json フィールド}`
- 津波リスト `https://www.jma.go.jp/bosai/tsunami/data/list.json`

**社員住所マスタ**（Googleスプレッドシート）

- [安否アラート用_社員住所マスタ（都道府県・市区町村）](https://docs.google.com/spreadsheets/d/1GorFs9jPr4DVMXrd7CUVvefwJibzCrft5LhYm3Xqoy0/edit)
- 列: `社員番号 / 氏名 / 部署 / 都道府県 / 市区町村`（2026/5時点 121名）
- 「住民税リスト（令和7年度）Arc_v2.xlsx」から抽出。**番地・建物名・郵便番号・生年月日は
  意図的に持たせていない**（通知に出す必要がなく、持たないことが最も確実な保護になるため）

## セットアップ

### 1. Slack Incoming Webhook を作る

1. https://api.slack.com/apps → **Create New App** → From scratch → 名前は `TERASS災害アラート`、
   ワークスペースは Terass
2. **Incoming Webhooks** を On にする
3. **Add New Webhook to Workspace** → 投稿先に `#p_saigai` を選ぶ
4. 発行された `https://hooks.slack.com/services/...` を控える

> `#p_saigai` はプライベートチャンネルなので、選択肢に出ない場合は先に Slack で
> `/invite @TERASS災害アラート` してからやり直す。

### 2. GASプロジェクトを作る

1. https://script.google.com → **新しいプロジェクト**（名前: `TERASS災害アラート`）
2. `Code.gs` の中身を全文貼り付けて保存
3. 左メニュー **プロジェクトの設定** → タイムゾーンを **日本標準時** にする

### 3. Webhook URL を登録する

**プロジェクトの設定 → スクリプト プロパティ → プロパティを追加**

| プロパティ | 値 |
|---|---|
| `SLACK_WEBHOOK_URL` | 手順1で控えたURL |

> URLはコードに直接書かない。GitHubに載せないための措置。

### 4. 初回実行して権限を承認する

エディタで `setup` を選んで実行する。初回はスプレッドシートと外部通信の承認を求められるので許可する。
成功すると `#p_saigai` に「セットアップ完了・121名読み込み」と投稿される。

### 5. トリガーを設定する

左メニュー **トリガー** → **トリガーを追加**

| 項目 | 値 |
|---|---|
| 実行する関数 | `main` |
| イベントのソース | 時間主導型 |
| 時間ベースのトリガー | 分ベースのタイマー |
| 間隔 | **5分おき** |
| エラー通知 | 毎日（推奨） |

これで運用開始。5分ごとに気象庁を見に行き、条件に合う地震・津波があったときだけ投稿する。

### 6. 疎通確認

`testLatestQuake` を実行すると、**しきい値を無視して**直近の地震1件を突合し、
`【テスト送信】` 付きで `#p_saigai` に投稿する。通知の見え方を確認したいときに使う。

Slackに投稿せずログだけ見たい場合は `dryRunLatestQuake` を実行する。

## 通知される条件

| 事象 | 条件 | 通知 |
|---|---|---|
| 地震 | 社員の居住地で **震度4以上** | 該当社員リスト付きで投稿 |
| 地震 | 社員の居住地で **震度5弱以上** | 上記に `@channel` と安否確認の呼びかけを追加 |
| 地震 | 震度4以上だが該当社員なし | 「該当社員はいません」と1行で投稿 |
| 地震 | 続報で震度が上がった | 「（続報）」として再通知 |
| 津波 | 津波注意報以上が発表 | 対象予報区と、予報区名に居住県を含む社員を投稿 |
| 上記以外 | — | **何も投稿しない** |

平常時は完全に無言なので、チャンネルが通知で埋まることはない。

## 突合の仕組み

気象庁は市区町村名を独特の表記で出すため、以下を吸収している（`cityMatchKind`）。

| 気象庁の表記 | マスタの表記 | 扱い |
|---|---|---|
| `福岡西区` | `福岡市` | 政令市。区が不明なので**市内全区の最大震度**を採り「市内最大」と注記 |
| `大阪平野区` | `大阪市平野区` | 区まで分かっているので、その区の震度をそのまま採用 |
| `東京世田谷区` | `世田谷区` | 東京23区は都道府県名が前置される |
| `福岡古賀市` | `古賀市` | 同名市町村の区別のため都道府県名が前置されることがある |
| `関ケ原町` | `不破郡関ケ原町` | 郡名は気象庁側に無い |

居住市区町村に観測点がない場合は、**都道府県の最大震度**にフォールバックして「県内最大」と
注記する。過検知は許容し、見逃しを避ける方針。

検証は `node gas/saigai-alert/test/match.test.js` で実行できる（実データ31項目、全通過）。

## 運用

**しきい値を変える** … `Code.gs` 冒頭の `ALERT_MIN`（通知する最低震度）と
`MENTION_MIN`（@channelを付ける震度）を書き換える。`'4'`, `'5-'`, `'5+'`, `'6-'` などで指定。

**社員の住所を更新する** … スプレッドシートを直接編集する。GASの変更は不要。
入退社や引越しが反映されるよう、住民税の更新時などに合わせて棚卸しするのが望ましい。

**通知を止める** … トリガー画面で `main` のトリガーを削除または無効化する。

## 既知の制約

- **対象は本部社員のみ**。Terass Agent（約1,500名）は住所マスタを持たないため対象外。
- **住所は住民票ベース**。単身赴任・長期出張・帰省中などの実際の所在は反映されない。
  あくまで「その地域に生活基盤がある社員」の把握であり、安否そのものの確認ではない。
- **津波の突合は粗い**。津波予報区（例:「有明・八代海」）は都道府県と1対1で対応しないため、
  予報区名に都道府県名が含まれる場合のみ社員を紐づけている。通知本文にもその旨を明記している。
- **気象警報（大雨・暴風の特別警報）は未対応**。都道府県ごとに別APIを叩く必要があり、
  地震・津波と比べて緊急度の設計が別途必要なため、初版では見送っている。
- 元データ（住民税リスト）で名古屋市が「古屋市」と誤記されていたため、マスタ生成時に補正済み。
  今後マスタを作り直す場合は同じ補正が必要。

## この仕組みの位置づけ

「安否確認システム導入」PJ（トヨクモ安否確認サービス2 等を検討中、9月導入判断予定）が本丸。
本システムはそれまでのつなぎであり、導入後も「どの地域に誰が住んでいるか」を人事が把握する
補完として使える。安否の回答収集・集計は専用システムの領域であり、本システムは行わない。
